# Architecture decision record

Rust 2024 workspace with Slint 1.16.0 pinned in Cargo.lock. Native Slint windowing; no browser runtime. UI owns presentation, application owns use cases, domain owns portable metadata, and engine owns process execution. Phase 1 diagnostic work runs outside the UI thread and returns through Slint's event loop. Engine calls are synchronous; future callers must use workers.

Use FFmpeg/FFprobe subprocesses rather than ABI bindings. One installer contains the editor and both executables; a single monolithic executable is not required. This avoids libav ABI coupling and retains explicit encoder build selection. Commands use argument arrays, null stdin, no shell and hidden process windows on Windows. Probe paths are canonicalized before execution. Discovery validates both version commands and rejects incomplete pairs. Debug supports FRAMEFORGE_FFMPEG_DIR then app resources then PATH; release uses only installed resources.

macOS: Contents/MacOS/uffmpeg and Contents/Resources/ffmpeg/bin/{ffmpeg,ffprobe}. Windows/Linux: ffmpeg/bin next to the editor. Vendor shared libraries must be bundled or helpers built with self-contained dependencies. macOS is aarch64-apple-darwin first; Windows x86_64-pc-windows-msvc and Linux x86_64-unknown-linux-gnu remain target boundaries, not verified builds.

Phase 2 adds a native rfd picker and session library with typed metadata and cached video thumbnails. Import executes off the UI thread; a Slint timer receives worker results and updates the library. Temporary preview ownership lives with each imported item. Native tool execution now uses continuously drained bounded pipes, output limits and deadlines with child kill/wait on failure. Phase 3 adds validated domain ranges, per-source range lists, a split application service and native split controls. Export stages each clip in its destination filesystem and validates output before no-overwrite publication. Re-encoding uses native MPEG-4/AAC; fast copy uses Matroska. The desktop submits immutable import/export requests to a FIFO worker; editing stays available and ordinary closing requests cancellation then waits for cleanup. Phase 4 adds a domain compatibility report, an application merge planner and engine concat/normalization methods. SHA-256 extradata hashes are captured during probing. The desktop previews compatibility from cached metadata and the application re-probes every file at export. Compatible copy uses a local-file-only escaped FFconcat manifest; normalization uses destination-local lossless FFV1/PCM intermediates with relative manifest entries and final MPEG-4/AAC encoding. Per-position audio tracks are padded with silence as needed. Single-output merge follows staged probe validation and no-overwrite persistence. Phase 5 introduces domain stream selections and audio formats, per-import selection state, explicit split mappings and a shared audio extraction service. Full-source or saved-range audio is exported one file per chosen source stream. Native audio output is staged, inspected and persisted without overwrite; all filenames and codec-copy choices are preflighted before a batch begins. AAC/M4A and PCM/WAV conversions are explicit options. The details panel uses source stream IDs and metadata tags; merge keeps its separate whole-source policy. Phase 6 centralizes immutable requests and FIFO execution in the application jobs module. The engine ExecutionControl handles cancellation, bounded pipe readers, FFmpeg progress, direct-child lifetime and publication gating. Desktop Jobs renders coalesced snapshots and queues new work without per-feature threads/timers. A dedicated metadata writer persists atomic history snapshots, with native locking and Interrupted recovery; shutdown drains the operation worker then flushes history. Remaining limitations: no playback, persistent editing projects, automatic partial resume, forced-kill cleanup guarantee or verified Windows/Linux runtime yet. No test cases are included by request.

Automatic batching extends the domain with a fixed-length planner and interval parser, including media-frame-aware video planning. Application wrappers re-probe duration and delegate generated ranges to the existing video/audio exporters, retaining staging and no-overwrite behavior. The desktop keeps automatic settings separate from each source's saved manual ranges and computes a local count preview. Both video and per-track audio support whole-source intervals. No new runtime dependency or encoder requirement was introduced.
