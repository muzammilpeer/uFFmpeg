# Build release packages yourself

For hosted builds and automatic draft Release uploads, see [GitHub releases](../../docs/github-release.md). The CI workflow uses the scripts below and does not publish automatically.

These scripts have not been executed end to end. The user-built macOS helpers now pass the native dependency/capability audit after correcting the exact `n8.1.3` version-label check. No installer, source bundle or signing submission was generated by the agent. Run the commands below, then complete the native installation review before distributing anything.

## Apple Silicon macOS

Requires Python 3.11+, Xcode Command Line Tools, Rust with the `aarch64-apple-darwin` target, Git and Homebrew build tools. On the current machine Meson and Ninja were missing. Native helper build paths must not contain spaces.

```sh
cd /Users/muzammilpeer/Git/uFFmpeg
brew install meson ninja
bash packaging/release/build-helpers.sh
bash packaging/release/macos.sh unsigned
```

The helper command builds pinned FFmpeg 8.1.3, dav1d 1.5.4 and zlib 1.3.2 from upstream commits. It installs nothing globally. Output is `packaging/vendor/aarch64-apple-darwin/`. The package command collects licenses and exact Rust sources, builds release Rust code, audits native dependencies, bundles helpers and their source/license records, ad-hoc signs the app and creates:

- `dist/uFFmpeg-0.1.0-macos-arm64-unsigned.dmg`
- `dist/uFFmpeg-0.1.0-macos-arm64-unsigned.source.tar.xz`
- `dist/uFFmpeg-0.1.0-macos-arm64-unsigned.SHA256SUMS`

The unsigned channel means **no Developer ID or notarization**, even though the local bundle has the ad-hoc signature required for development. It is suitable for local installation review, not a public notarized release. Drag the app from the DMG into Applications. The installed app uses its own media tools; Homebrew FFmpeg is not copied or required.

For a public build, first obtain a Developer ID Application certificate and store your notarization credentials in a `notarytool` Keychain profile using Apple's documented process. Then use the existing profile and certificate identity:

```sh
export UFFMPEG_SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)'
export UFFMPEG_NOTARY_PROFILE='your-existing-keychain-profile'
bash packaging/release/macos.sh signed
```

This explicitly signs helpers, signs the app, submits/staples its ticket, creates the DMG, and submits/staples the DMG. It does not request, store in files, or print your credentials. The signed channel uses separate output filenames. It makes notarization network submissions only when you run `signed`.

## Windows x64

Use a source checkout such as `C:\src\uFFmpeg`, without spaces. Install Rust MSVC, Visual Studio C++ Build Tools/Windows SDK, PowerShell 7, Inno Setup 6.x (6.3 or later, `ISCC.exe` on PATH), and MSYS2 UCRT64 with GCC, Git, Make, Meson, Ninja, pkg-config, NASM and xz. Add Rust's Cargo bin directory to the MSYS2 PATH for provenance recording.

In the **MSYS2 UCRT64 shell**:

```sh
cd /c/src/uFFmpeg
bash packaging/release/build-helpers.sh
```

In **PowerShell 7 with the Visual Studio x64 developer environment loaded**:

```powershell
cd C:\src\uFFmpeg
./packaging/release/windows.ps1
```

This embeds the app icon, requests the static MSVC CRT, rejects non-system DLL imports, and creates a per-user installer plus sources/checksums in `dist/windows-unsigned/`. It bundles FFmpeg/FFprobe and their static dependency/source records. Windows 10 build 19041 or later is the declared installer floor; clean-machine confirmation is still required.

For signed setup/uninstallers, set `UFFMPEG_CERT_THUMBPRINT` and `UFFMPEG_TIMESTAMP_URL` for your installed signing certificate and trusted HTTPS timestamp service, then invoke `./packaging/release/windows.ps1 -Signed`. The script signs payload executables and supplies Inno's SignTool so setup, its temporary copies and uninstaller are signed. No certificate purchase or signing service setup is automated.

## Linux x64 or ARM64

Use a native Debian/Ubuntu environment with Rust, build-essential, Git, Meson, Ninja, pkg-config, NASM (x64), xz-utils, binutils, dpkg-dev, and the Slint build dependencies listed in `docs/desktop.md`. Build on the oldest distribution you intend to support; newer glibc cannot be made compatible by changing the package description.

```sh
bash packaging/release/build-helpers.sh
export UFFMPEG_MAINTAINER='Your Name <your-email@example.com>'
bash packaging/release/linux-deb.sh
```

Creates `dist/uffmpeg_0.1.0_amd64.deb` (or `arm64`), exact source/records archive and checksums. The package contains its media tools. OS graphics, font and portal libraries remain declared native package dependencies; this is a Debian package, not an all-distribution AppImage. Install using `sudo apt install ./dist/uffmpeg_0.1.0_amd64.deb` on the intended Linux machine. Repository/package signing and non-Debian distribution are separate release-distribution choices.

## Records and repeat builds

Scripts refuse to replace an existing vendor directory or final package. Move previous outputs aside before rebuilding. Intermediate files live under `work/release/`; failed builds remain available for diagnosis. `BUILD_JOBS=1` lowers helper compiler parallelism when memory is limited.

The package collector stores dependency declarations, license texts, exact Cargo.lock, all vendored Rust source, project source and toolchain versions. FFmpeg, dav1d and zlib source archives and configuration travel inside the installed app. Keep the companion Rust source archive next to each published installer. Build manifests describe **unsigned helper binaries**; signing changes those hashes, so the macOS/signed Windows payload labels them accordingly. Final installer/source SHA256SUMS describe the published files.

Collection is not license approval. Missing license text stops packaging and identifies the crates to review. Review the actual Slint royalty-free desktop terms and preserve About Slint; inspect all transitive terms and upstream notices. FFmpeg configuration disables GPL/nonfree/version3 additions and automatic external dependency discovery. It intentionally retains MPEG-4/AAC/PCM/FFV1 encoding, CPU AV1 decoding through static dav1d, and static zlib for compression/PNG support. No libx264/libx265, network streaming or system FFmpeg fallback is enabled.

The checked upstream tags map to immutable commits in `sources.env`; these are source pins, not a claim of byte-for-byte reproducibility across compiler/SDK versions. All packaging code, especially Windows/installer behavior, still needs its first actual run.

## Release acceptance

Before distribution, install on clean supported OS images without FFmpeg on PATH. Confirm helper discovery, Unicode/spaced media paths, thumbnail import, split/merge/audio/automatic batching, cancellation/recovery, output reveal, accessible license records, upgrade and uninstall behavior. Confirm private libraries are absent or correctly bundled, signatures/notarization succeed, the companion source archive can rebuild offline for Rust, and the stated deployment floor is accurate. No test cases are supplied.

References: [FFmpeg releases](https://ffmpeg.org/download.html), [FFmpeg license policy](https://ffmpeg.org/legal.html), [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), [Inno signing](https://jrsoftware.org/ishelp/topic_setup_signtool.htm), [Debian dependency policy](https://www.debian.org/doc/debian-policy/ch-sharedlibs.html).

## Recover a completed helper build

If compilation finished but the final audit rejected it, keep the `work/release/<target>/helpers.*` directory. After correcting the reported issue, reuse that exact directory:

```sh
bash packaging/release/build-helpers.sh --resume work/release/aarch64-apple-darwin/helpers.YOUR-BUILD-ID
```

This verifies the three pinned source revisions and reruns all helper audits before promoting the completed bundle. It does not recompile. For a source checkout FFmpeg may report `n8.1.3`; both `n8.1.3` and `8.1.3` are accepted as the exact pinned version. Additional suffixes or different versions are rejected. Once the vendor directory exists, run the package command directly.
