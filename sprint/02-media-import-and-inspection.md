## Implementation notes

Native multi-select uses rfd 0.17.2. The picker starts on the UI thread for macOS; FFprobe and thumbnail generation run sequentially on a worker, with results delivered through a Slint timer/channel. Import preserves returned picker order and exposes explicit Move up/Move down and Remove controls. Removing a library item leaves its source untouched. Canonical paths prevent repeat imports of the same path; hard-link aliases are not deduplicated.

Import validates regular, readable, nonempty files and requires at least one audio/video stream. Failure of one file does not discard other selected files. Video previews are generated into application-owned temporary directories, cleaned when items leave the library or the application exits normally. Preview failures retain the item and show a warning. Audio-only sources show a clear placeholder. Metadata shows duration, container, stream indexes, codecs, resolution, frame rate, sample rate and channel count where available.

Native helper calls have deadlines (10 seconds for version queries; 20 seconds for probe/thumbnail) and file-backed output with a 4 MiB inspection limit, checked every 40 ms. These are best-effort bounds, not operating-system resource quotas. Large batches currently report completion together; per-file progress/cancellation and shutdown coordination remain Phase 6.

Manual CLI inspection: `cargo run -p frameforge-desktop -- --inspect /absolute/path/to/media.mp4`. This runs the same validation and thumbnail service as UI imports. It does not preserve the preview after the command exits.

No test cases added. UI picker, duplicate skips, reordering, removal and visual layout require interactive review; automation could not open the development app within its time limit. Windows/Linux remain unverified.
